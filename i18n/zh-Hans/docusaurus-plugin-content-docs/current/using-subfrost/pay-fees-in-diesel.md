# 用 DIESEL 支付手续费

每一笔 Bitcoin 交易都要向矿工支付网络手续费，而这笔手续费始终以 BTC 支付。如果你持有 DIESEL，但几乎没有或完全没有 BTC，就可能卡在这一步。

SUBFROST Chrome 扩展和 Android 应用让你可以改用 **DIESEL** 支付这笔手续费。一个中继方（relayer）会把自己的 BTC 加入你的交易来支付矿工，而你在**同一笔交易**中用 DIESEL 向它付费。你不需要为手续费准备 BTC。

想了解它在底层是如何运作的？请参阅 [DIESEL 手续费的工作原理](../protocol/diesel-fees)。

## 在哪里找到它

当某个操作支持这一功能时，你会看到一行 **网络费用**，其中有两个选项：**BTC** 和 **DIESEL**。

在 <a href="https://chromewebstore.google.com/detail/subfrost/pcmlnnfmcdmaifmleedbhomhaeldkeen" target="_blank" rel="noopener noreferrer">Chrome 扩展</a>和 <a href="https://subfrost.io/download/android" target="_blank" rel="noopener noreferrer">Android 应用</a>中，这一行都位于 **Send（发送）** 界面和 **Swap（交换）** 界面。

默认选项是 BTC。如果你的 BTC 不足以支付手续费，钱包会自动切换到 DIESEL，并提示你：*“BTC 不足以支付手续费。已选择 DIESEL。”*

## 核对手续费

当你选择 DIESEL 并继续时，确认页面会把手续费显示为 **最多 X DIESEL**。在扩展中，它显示为 *“以 DIESEL 支付，最多 X DIESEL”*。

这个数字是一个**上限**，而不是固定价格：

- 钱包会根据当前的 DIESEL 价格估算手续费，然后在此基础上加上一小部分余量。这就是你在确认页看到的“最多”那个数字。
- 实际收取的金额由手续费报价决定，可能低于这个上限。
- 如果报价**高于**你批准的上限，钱包会停止操作，不会发送任何内容。你会看到 *“DIESEL 价格已超出你批准的上限。未发送任何内容。”*

:::note[请把 DIESEL 放在你的 taproot 地址中]
手续费从你 taproot 地址中的 DIESEL 支付。如果那里的 DIESEL 不够，你会看到 *“你的 taproot 地址中的 DIESEL 不足以支付此手续费。”*
:::

钱包处理过程中会显示进度提示，例如 *正在读取你的币…*、*正在连接手续费网络…*、*正在读取 DIESEL 价格…*、*正在获取手续费报价…*、*正在签名…*、*正在添加手续费…*（Android 应用显示的提示会少一些）。

## 哪些操作可以用 DIESEL 支付

在 Chrome 扩展和 Android 应用中都支持：

- **发送 BTC** 给单个收款人。
- **发送代币** 给单个收款人。
- 在代币之间进行 **交换**。
- 把 BTC **包装** 为 frBTC。
- 把 frBTC **解包** 为 BTC。

Android 应用还支持在 [BTCUSD 资金池](./btcusd-pool) 中交易 frBTC 和 frUSD 时使用它。

当你用 DIESEL 手续费解包时，确认页面会多出一行：*“你将收到 X BTC，扣除付款交易的手续费。”* 向你支付 BTC 的是另一笔单独的交易，它自己的手续费会从你解包的金额中扣除。

## 不支持的情况

在以下情况下，DIESEL 选项会变灰，并在下方显示一行简短的原因：

- **发送给多个收款人。** *“DIESEL 手续费仅适用于单个收款人。”*
- **一侧是 BTC 的交换**，普通的包装或解包除外。*“与 BTC 的兑换不支持 DIESEL 手续费。”* 你可以改为从 frBTC 发起交换，或者这一笔用 BTC 支付。
- Android 应用中的**硬件钱包。** *“硬件钱包不支持 DIESEL 手续费。”*
- **主网以外的网络。** *“DIESEL 手续费仅在主网可用。”*

**dApp 请求你签名的交易**始终以常规方式用 BTC 支付手续费。DIESEL 手续费仅适用于你在钱包内部发起的操作。

## 当 DIESEL 不可用时

这笔手续费是在一个中继方网络的帮助下支付的。当钱包打开 Send（发送）或 Swap（交换）界面时，它会在后台检查该网络此刻能否接受 DIESEL 付款。

如果不能，钱包会告诉你，并保持选择 BTC：

- *“当前无法使用 DIESEL 支付手续费。暂时仅支持 BTC。”*
- *“手续费网络当前繁忙。请用 BTC 支付手续费，或一分钟后重试。”*
- 如果你的 BTC 同时也不够：*“BTC 不足以支付手续费，且当前无法使用 DIESEL 支付。”* 这种情况下，请补充一点 BTC，或稍后再试。

## 如果中途出了问题

大多数问题都发生在发送任何内容之前，钱包会清楚地告诉你。以 **“未发送任何内容。”** 结尾的提示意味着你的币没有动。你可以重试，或者改用 BTC 支付。

例如，手续费报价只在很短的时间内有效。如果在使用前就过期了，你会看到 *“手续费报价在使用前已过期。未发送任何内容。请重试。”*

有一种情况需要谨慎处理。如果你已经签名，而手续费网络随后没有响应，你会看到：

> *“签名后手续费网络没有响应。再次发送前，请在区块浏览器中查看交易 …。”*

你的交易仍然可能成功。**在重试之前，请先在区块浏览器中查询这笔交易。** 如果它已经确认，就无需再做任何事。在这种情况下，钱包不会自动为你切换到 BTC 手续费。在查证之前不要重新发送，否则可能会付两次。

## 常见问题

**我完全不需要 BTC 吗？**
手续费不需要。但对于 **发送 BTC** 和 **包装**，你仍然需要准备好要发送或包装的那部分 BTC。

**批准时价格就固定了吗？**
上限是固定的。你批准的是“最多 X DIESEL”，钱包不会超过它。最终收取的金额可能更低。

**为什么显示“最多”而不是一个确切数字？**
确切金额来自你批准之后片刻获取的一个新报价。如果价格在这期间变动，上限会保护你。

**这是一笔单独的交易，还是一笔借款？**
都不是。中继方的 BTC 和你的 DIESEL 付款在同一笔 Bitcoin 交易中。请参阅 [DIESEL 手续费的工作原理](../protocol/diesel-fees)。

**可以在 dApp 中使用吗？**
不可以。来自 dApp 的请求用 BTC 支付手续费。

**我的 DIESEL 去了哪里？**
它会被支付到链上的一个协议金库（treasury）中。[DIESEL 手续费的工作原理](../protocol/diesel-fees) 会解释细节。
