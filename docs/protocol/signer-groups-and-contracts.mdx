# Signer Groups and Contracts

This page is the registry. It lists every signer group SUBFROST runs, what each one may sign, and its public address. It also lists every contract and alkane id the pegs depend on. Every entry was read back from its chain before it was published; the method for each is noted next to it, so you can check it yourself.

## Two kinds of group

SUBFROST runs two kinds of threshold group. Both have the same property: the full key never exists in one place, and a quorum has to cooperate to sign (see [Signing and Keys](./signing-and-keys)).

- **FROST groups hold value.** They produce one BIP-340 Schnorr signature, which is a native Bitcoin signature and is also what the frUSD vault on Ethereum verifies. A FROST group's key **is** the custody: on Bitcoin it is a taproot address, and on Ethereum it is the vault's `defaultPublicKey`.
- **cggmp21 groups pay gas.** cggmp21 is threshold ECDSA, which produces the ordinary signature an EVM transaction needs. Each of these groups controls one Ethereum-style address (an EOA) that broadcasts transactions and pays their gas. **None of them can move user funds.** What a transaction does is already fixed by a user's signed intent, by a FROST signature, or by a contract that only ever pays one fixed recipient. A stolen cggmp21 key can waste its own gas and nothing else.

## FROST groups (Bitcoin and Fractal)

| Group | Threshold | Signs | Public address |
|---|---|---|---|
| **frBTC** | nine signers (see [frBTC Peg & Custody](./frbtc-peg-and-custody)) | BTC payouts from custody when frBTC is unwrapped | `bc1p5lushqjk7kxpqa87ppwn0dealucyqa6t40ppdkhpqm3grcpqvw9s3wdsx7` |
| **frUSD** | 2-of-3 launch group, being widened to 6-of-9 | frUSD mints on Bitcoin, and every privileged call on the frUSD vault on Ethereum (releases, strategy changes) | `bc1pk6nv75fp4cav5zq3vrl98rwynq0e9lazqcygvqa2fqd6agnd95cskcz0kw` |
| **frFB** | 6-of-9 | frFB mints on Bitcoin, and FB redemptions out of the fb-vault on Fractal | `bc1pt93aunap64ys8zlpmzc20z65a2vnmn0phrpc37kknve5835xsc9s6332rc` (the same string on Fractal) |

**How to check each one.**

- **frBTC.** Call opcode 103 on `32:0`. It returns the group's **untweaked** x-only key, `7940ef3b659179a1371dec05793cb027cde47806fb66ce1e3d1b69d56de629dc`. Apply the BIP-341 taproot tweak (key path only, no script tree) to get output key `a7f90b8256f58c1074fe085d37b73dff3040774babc216dae106e281e020638b`, which is the address above. Encoding the opcode-103 key directly, without the tweak, gives a different address that is **not** custody.
- **frUSD.** The address holds frUSD's mint authority, `frUSD-MINT` (`2:92949`). Its 32-byte output key, `b6a6cf5121ae3aca081160fe538dc4981f92ffa206088603aa481baea26d2d31`, is byte for byte what `defaultPublicKey()` returns on the frUSD vault `0x95779E7E1C943042255B8a78273fe6DE4823CF06`. One key, two chains. Widening the group is a key rotation, itself signed by the group; nothing is redeployed. The threshold has no effect on gas: the vault always verifies a single 64-byte signature.
- **frFB.** On Bitcoin the address holds `frFB-AUTH` (`2:102485`). On Fractal, fb-vault (`44:44`) opcode 104 returns `5120 5963de4fa1d549038be1d8b0a78b54ea993dcde1b8c388fad69b3343c686860b`: exactly this address's script. Opcode 103 returns its untweaked key, `ca1240110a6354160fbb8e726340352e38478af4f2a34c9b04893741c5d49203`. See [Fractal](../fractal/overview).

Example `settleMany`: [`0x7aaee3bf…4de4`](https://etherscan.io/tx/0x7aaee3bfb40647b20f62d07eba343c3fd966a2450bc0250ac0a6e0a14da94de4) |
| **claim** | 2-of-3 | `claim` on the peg-out `EscrowFactory`: delivers a peg-out that landed at a recipient's delivery escrow | `0xCE4d3f82ad29a0AE8d99781D81284677d95c38c9` | Funded on Ethereum, Base, BNB Chain and Polygon; has not sent a transaction yet |
| **gasdrop-claim** | 2-of-3 | Deploys and pokes [gas-drop handlers](../developer-guide/encoding-pegs-and-swaps#optional-gas-drop) registered with pegd. Until it runs, anyone can deploy a handler with `deployOnly` | not created yet | **Coming** (the registry it reads is live) |

Each of these calls is also open to anyone: `register`, `settle`, `reclaim`, `claim` and the forwarders' entry points are all permissionless. The groups are there so that you don't have to send them yourself, not because nobody else can.

## Contracts

The same hex address can be a different contract on a different chain, so always name a contract with its chain. Every address below was checked for code on its chain, plus a read that ties it to its role.

| Contract | Address | Role |
|---|---|---|
| `GatewayFactory` | `0xaF4C39A0Da304eF39D56783d785ea52bb8431362` | Derives peg-in deposit addresses; `register`, `settle`, `settleMany`, `reclaim`; relays into the frUSD vault |
| `GatewayProxy` implementation | `0xdbA4c9fe841A7cf0b37B041126bA4d4640B4F296` | The code every deposit address clones (`IMPLEMENTATION()` on the factory) |
